# JS 프로토타입 정리

## 핵심

> 함수를 선언하는 순간 Constructor.prototype이 자동으로 생성된다.
> 이후 new 키워드로 인스턴스를 만들면 **proto**라는 숨겨진 프로퍼티가 자동으로 생기고, 상위 객체인 Constructor.prototype을 참조하게 된다.
> **proto**는 생략 가능하도록 설계되어 있기 때문에 인스턴스에서 prototype에 있는 메서드를 마치 자기 것처럼 호출할 수 있다.

### 예시

```js
function Person(name) {
  this.name = name;
}
// 이 순간 이미 Person.prototype 존재

Person.prototype.greet = function () {
  return `안녕, 나는 ${this.name}이야`;
};

const jimin = new Person('지민');
// 이 순간 jimin.__proto__ 생성 → Person.prototype 연결

jimin.greet();

// jimin 안에는 greet가 없음
// __proto__를 통해 Person.prototype.greet를 찾아서 실행

console.log(jimin.__proto__ === Person.prototype); // true
```

---

## 프로토타입 구조

메서드/프로퍼티를 찾을 때 없으면 `__proto__`를 타고 위로 올라가며 탐색한다.

```
instance
  └── Constructor.prototype     ← 여기서 먼저 찾음
        └── Object.prototype    ← 없으면 여기서 찾음
              └── null          ← 여기까지 오면 undefined
```

### 실제 예시 (배열)

```
arr
  └── Array.prototype      ← map, filter, forEach, push ...
        └── Object.prototype  ← toString, hasOwnProperty ...
              └── null
```

`arr.map()`을 쓸 수 있는 이유 → `arr`에는 없지만 `Array.prototype`에 있기 때문

## `prototype` vs `__proto__`

|                         | 누가 가지나  | 의미                                         |
| ----------------------- | ------------ | -------------------------------------------- |
| `Constructor.prototype` | 함수(생성자) | new로 만든 인스턴스들이 공유할 메서드 저장소 |
| `instance.__proto__`    | 인스턴스     | Constructor.prototype을 가리키는 참조        |

```js
Person.prototype === jimin.__proto__; // true → 같은 객체를 바라봄
```

삼각형 그림이 이 한 줄을 시각화한 것.

- **실선** → Constructor에서 Constructor.prototype으로 직접 연결
- **점선 대각선** → Constructor.prototype과 instance.**proto**가 같은 곳을 참조
- **점선 세로** → new로 instance 생성

결국 세 꼭짓점(Constructor, Constructor.prototype, instance)의 관계를 한눈에 보여주는 것.

## ⚠️ `__proto__` 직접 호출 시 undefined가 뜨는 이유

```js
var Person = function (name) {
  this._name = name; // new 실행 시 suzi 본인한테 저장
};
Person.prototype.getName = function () {
  return this._name;
};

var suzi = new Person('Suzi');
```

```js
suzi.getName(); // "Suzi" ✅ → this = suzi
suzi.__proto__.getName(); // undefined ❌ → this = Person.prototype
```

`__proto__`를 생략하면 `this`는 suzi, 직접 쓰면 `this`는 `suzi.__proto__`(= `Person.prototype`)가 된다. `_name`은 suzi 본인한테 저장되어 있어서 `Person.prototype`에서는 찾을 수 없으니 undefined.

> `_name`은 `new` 실행 순간 **suzi 본인**한테 저장되는데,  
> `__proto__`를 직접 호출하면 탐색 시작점이 suzi를 건너뛰어버려서 못 찾는 것.

## prototype에 있는 것 vs 없는 것

**prototype에 있는 메서드만** 인스턴스가 `__proto__` 타고 자기 것처럼 쓸 수 있다.
prototype 밖에 있는 건 생성자 함수에서 직접 호출해야 한다.

```js
var arr = [1, 2];

arr.forEach(function () {}); // ✅ Array.prototype에 있음 → __proto__ 타고 접근 가능
Array.isArray(arr); // ✅ Array 자체에 있는 정적 메서드 → 직접 호출
arr.isArray(); // ❌ TypeError: arr.isArray is not a function
```

### 구조로 보면

```
Array (생성자 함수)
  ├── from()       ← 정적 메서드 (인스턴스에서 직접 호출 불가)
  ├── isArray()    ← 정적 메서드 (인스턴스에서 직접 호출 불가)
  └── prototype
        ├── push()
        ├── pop()
        ├── forEach()
        ├── map()
        ├── filter()
        └── ...    ← 이것들만 인스턴스가 자기 것처럼 쓸 수 있음
```

> **prototype 안 = 인스턴스가 쓸 수 있음**
> **prototype 밖 = 생성자 함수에서 직접 호출해야 함**

## Constructor 프로퍼티

`prototype` 안에는 `constructor`라는 프로퍼티가 자동으로 생긴다. 이 프로퍼티는 자기 자신(생성자 함수)을 참조한다.

```js
var arr = [1, 2];

Array.prototype.constructor === Array; // true
arr.__proto__.constructor === Array; // true
arr.constructor === Array; // true (__proto__ 생략)
```

`__proto__` 생략 가능하니까 인스턴스에서 바로 `constructor`에 접근할 수 있다.

```js
// arr.constructor === Array 이므로 아래도 가능
var arr2 = new arr.constructor(3, 4);
console.log(arr2); // [3, 4]
```

> `constructor`는 인스턴스로부터 자신을 만든 생성자 함수가 뭔지 알 수 있는 수단.
> 단, constructor를 바꿔도 실제 인스턴스의 원형은 바뀌지 않으므로 항상 신뢰할 수는 없다.

---

## Constructor 변경

```js
// constructor 바꿔도 실제 원형은 안 바뀜
d.constructor = NewConstructor;
d instanceof NewConstructor; // false
```
