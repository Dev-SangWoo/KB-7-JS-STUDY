# 6-2-1. 메서드 오버라이드

## 1. 메서드 오버라이드란?

자바스크립트 객체는 자신의 부모 역할을 하는 `prototype`으로부터 메서드를 상속받아 사용할 수 있다. 

그런데 **자신(인스턴스)이 부모와 똑같은 이름의 메서드를 직접 가지고 있다면:**

```jsx
 var Person = function (name) {
	 this.name = name;
 };
 
 Person.prototype.getName = function () {
	 return this. name;
 };

 var iu = new Person('지금');
 iu. getName = function () {
	 return '바로' + this.name ;
 };
 
 console.log(iu.getName()) ;  //바로 지금
```

- **예제 상황:**
    1. `Person.prototype.getName`이라는 메서드가 이미 존재한다.
    2. 그런데 인스턴스인 `iu` 객체에 직접 `iu.getName`이라는 메서드를 새로 정의한다.
- **결과:** `iu.getName()`을 실행하면 부모의 메서드가 아닌, **자신이 가진 메서드가 호출된다**.

## 2. 왜 내 것이 먼저 호출될까? (자바스크립트 엔진 메서드 탐색 순서)

1. **자신의 프로퍼티**를 먼저 검색한다.
2. 없으면 그다음으로 가까운 `__proto__` (부모 프로토타입)를 검색한다.

이미 `iu` 본인에게 `getName`이 있기 때문에 부모까지 올라갈 필요가 없어서 검색 순서에서 밀리게 되는 것이다.

## 3. 가려진 부모의 메서드 호출하기

오버라이드 때문에 부모의 메서드가 가려졌지만, 아예 접근할 수 없는 것은 아니다.

하지만 단순히 호출하면 문제가 생긴다.

- **잘못된 접근:** `iu.__proto__.getName()`
    - 이렇게 호출하면 메서드 안의 `this`가 인스턴스(`iu`)가 아닌 부모(`prototype`) 객체를 가리키게 된다.
    - 따라서 `this.name`을 찾지 못해 `undefined`가 출력될 수 있다.
- **해결 방법:** `call` 또는 `apply` 사용
    - `iu.__proto__.getName.call(iu)`
    - 부모의 메서드를 빌려 쓰되, **`this`는 나(`iu`)를 바라보게 강제로 고정한다**.
    - 이렇게 하면 오버라이드된 상황에서도 원본 부모 메서드를 성공적으로 실행할 수 있다.

# 6-2-1. 프로토타입 체인

### 1. 모든 길은 '객체'로 통한다

자바스크립트에서 배열이나 함수 같은 복잡한 데이터 타입들은 결국 '객체'를 기반으로 한다.

- **객체의 내부:** 일반적인 객체를 열어보면 `__proto__` 안에 `hasOwnProperty`, `toString` 같은 기본 메서드들이 들어 있다.
- **배열의 내부:** 배열을 열어보면 첫 번째 `__proto__`에는 `push`, `pop` 같은 배열 전용 메서드들이 있다. 그런데 이 안을 한 번 더 열면(두 번째 `__proto__`), 앞서 본 객체의 기본 메서드들이 또 나온다.
- **이유:** **배열도 결국은 객체**이기 때문에, 객체의 기능을 물려받아야 하기 때문이다.

### 2. 프로토타입 체이닝

데이터의 `__proto__`가 연쇄적으로 이어져 있는 것을 **프로토타입 체인**이라 하고, 이 길을 따라 원하는 기능을 찾아가는 과정을 **프로토타입 체이닝**이라고 한다.

- **찾는 과정:** `내 것` → `부모(Array)의 것` → `조부모(Object)의 것` 순서로 검색한다.
- **실제 예시:** 배열에서 `toString()`을 호출하면, 배열 전용 `toString`이 있으면 그걸 쓰고, 없으면 객체의 `toString`까지 올라가서 찾아낸다.

### 3. 데이터 타입별 구조

자바스크립트의 모든 데이터(Number, String, Boolean 등)는 이와 비슷한 삼각형 구조를 가집니다.

- 각자의 전용 기능을 담은 프로토타입(예: `Number.prototype`)을 거쳐, 최종적으로는 모두 `Object.prototype`에 도달하게 된다.
- 즉, `Object.prototype`은 자바스크립트 모든 객체의 종점이라고 할 수 있다.

# 요약

- 6-2-1: 자바스크립트가 "가장 가까운 곳부터 찾는다"는 규칙을 설명하고 있다. 내가 같은 이름의 기능을 가지고 있으면 부모 것은 잠시 가려지지만, 필요하다면 `call` 같은 도구를 이용해 우회해서 부모의 기능도 꺼내 쓸 수 있다.
- 6-2-2: 자바스크립트는 프로토타입 체인이라는 길을 통해 조상의 기능을 내 것처럼 편하게 쓸 수 있게 설계되어 있다. 이 체인의 가장 마지막 종점은 언제나 `Object.prototype`이라는 점을 기억하자.
